Test Plan — Uber Rider Mobile App

Purpose

Test major rider workflows with a risk-based manual QA approach.

Objectives

Verify account access, locations, ride selection/request, driver/trip information, post-trip/payment flows, and applicable safety tools.

Entry Criteria

App launches; test account exists; network works; required permissions can be controlled.

Exit Criteria

Critical/high cases have results; critical failures are documented; smoke testing is complete; blockers and risks are recorded.

Status Definitions

PASS = actual matches expected. FAIL = actual differs. BLOCKED = dependency prevents execution. NOT RUN = not executed.

Risks

Features, prices, ride availability, and behavior can differ by city, account, device, OS, and app version.

Deliverables

Test plan, detailed test cases, smoke/regression checklists, sample defect reports, and execution report.
